# WorkBuddy 冒烟测试规程

目的：花 10 分钟弄清 WorkBuddy 的运行环境能扛到哪一步，再决定完整模式还是轻量模式。
方法：在 WorkBuddy 里新建任务，把每关的指令原样粘贴发送，把它的回复与产物逐关记录（通过 / 失败 / 失败原文）。

## 第 0 关 · 技能识别

指令：

> 你装了 lemo-opuscar 技能吗？用一句话说清这个技能是干什么的，并列出它 scripts 文件夹里的文件名。

通过标准：能复述「用代码直接生成短片」且说得出 `setup.sh`。说不出 = 技能没装好，先解决导入，不要往下测。

## 第 1 关 · Shell 与运行时

指令：

> 请实际运行命令（不要凭印象回答），报告这个环境的：操作系统、node --version、python3 --version、ffmpeg -version 第一行、git --version。哪条跑不了就报哪条错。

通过标准：四条命令都有真实输出。任何一条「无法执行命令」= 无 shell，结论直接跳到「咨询模式」，规程结束。

## 第 2 关 · 拉库与装依赖

指令：

> 在当前工作目录运行：`git clone https://github.com/demonyc88888/lemo-opuscar.git wb-test && cd wb-test && sh plugin/skills/lemo-opuscar/scripts/setup.sh`，把最后 3 行输出原样发我。先不要装依赖。

通过标准：输出含 `LIB=` 且指向刚克隆的目录。再继续：

> 接着运行 `sh plugin/skills/lemo-opuscar/scripts/setup.sh deps`，完成后报告 node_modules 和 python 环境是否就绪；中途失败把报错原文发我，不要自己换方法绕。

通过标准：deps 完成（这一步要下载无头 Chromium，慢是正常的；**若任务被平台时长上限掐断，记录掐断时点**——这是后面判断能否长渲染的关键证据）。

## 第 3 关 · 单帧渲染

指令：

> 用已克隆库里 white-model 风格的 demo 源码渲染一帧静帧（按 core/TECHNIQUE.md 的 still 渲染法，1920×1080），把图片发我看。

通过标准：拿到一张真渲染的白模投影风格帧（不是文字描述、不是找来的图）。

## 第 4 关 · 10 秒短片 + 离线配音

指令：

> 做一支 10 秒测试片：蓝图风格，题目「一把折叠椅」，中文旁白 2 句，用离线 Kokoro 配音（先按 setup 的 tts 步骤装好），最后报告成片路径、时长和响度。

通过标准：成片存在、可播放、有中文配音、响度约 −14 LUFS。

## 结论表（测完回填）

| 结果 | 用法 |
|---|---|
| 0–4 关全过 | 完整模式：可正式接片，再跑 `compat/BENCHMARK.md` 基准片定级 |
| 卡在第 4 关（模型下载/长任务） | 半完整：可渲染，配音改走在线 edge-tts，或旁白回本地补 |
| 卡在第 2–3 关 | 轻量模式：只做前期（选风格/TREATMENT/分镜），渲染回本地 |
| 卡在第 0–1 关 | 咨询模式：只当风格与文案顾问 |

把逐关记录（尤其是失败原文与掐断时点）发回 fork 维护者，记入 `compat/results/workbuddy.md`。
